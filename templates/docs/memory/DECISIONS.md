# DECISIONS（决策 + 理由；各线共用）

## 规则
- **只有总控写本文件。** 子会话把候选决策写进回报的"值得记忆"一节，由总控验收时追加。
- 只在末尾追加。**唯一例外**：被取代的旧条目，可以把它的"状态"一行改成 `作废→<新编号>`，其他内容一律不动。
- 编号 `D-<线名>-<三位序号>`，序号在本线内递增，几条线同时追加也不会撞号。
- 标签 1–3 个，小写英文，如 `#db` `#api` `#ui` `#build`。新建标签前先 Grep `标签：` 看已有的，能复用就复用。
- **追加前先查冲突**：Grep 同标签、状态为"有效"的条目。新决策和它矛盾时：
  - 旧条目是本线的 → 新条目"取代"写旧编号，旧条目状态改成 `作废→<新编号>`。
  - 旧条目是别的线的 → 先停下，用 AskUserQuestion 问用户；用户同意才取代。
- 作废的条目在合并到 main 时搬到 `ARCHIVE.md`（见 workflow.md §8），本文件只留有效条目，保持短。

## 格式
### D-<线名>-001 决策标题
- 日期：YYYY-MM-DD
- 标签：#xxx
- 状态：有效（被取代后改成：作废→D-<线名>-00N）
- 决定：
- 理由：
- 放弃的方案：
- 取代：无（或被取代条目的编号）
