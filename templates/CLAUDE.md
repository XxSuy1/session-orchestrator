# 项目入口（保持精简）

## 工作流
本项目按总控协议运行，规则见 @.claude/rules/workflow.md。一个项目可以同时有多个总控，各管一条功能线（`docs/lines/<线名>/`）；总控只指挥不干重活，子会话只做被分配的一张任务卡。

## 总览（自动导入）
@docs/memory/STATE.md

## 会话协议
- 开始：先看上面的总览。你若是某条线的总控：若本线 `HANDOFF.md` 内容不是空模板，先读它；再读本线 `STATE.md`、`TASKS.md` 和共用的 `DECISIONS.md`，用三句话复述本线状态再动手。用户要你开新线或接手某条线时，按 `workflow.md` §2 做。
- 结束前按 `workflow.md` §9 的收尾清单逐项过一遍。
- 结束：更新本线 STATE.md（只写当前状态）和总览里自己那一行；有决策追加 DECISIONS.md；有坑追加 GOTCHAS.md。
- 你若是子会话：读任务卡 → 动手前把细计划写成任务卡同目录的 `<编号>.plan.md` → 只做任务卡范围 → 详细产出写文件 → 回报"状态｜结论｜文件路径"，并附检查命令与输出。
- 提交只写明确的文件路径，不用 `git add -A`。
